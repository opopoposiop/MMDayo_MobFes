# モブフェス・ペンライト

[MikuMikuDayo](https://github.com/pennennennennennenem/MikuMikuDayo) 向けのライブ会場用ペンライトモデルです。観客の身体は含まず、2種類の形状を合計4000本、平面上へ再現可能な疑似乱数で配置します。

発光部は1000本ずつ4系統に分かれ、初期状態で緑・桃・青・橙の4色を同時表示します。それぞれ独立したHSV系カラーモーフと、[MMDayo_AL（PPAL）](https://github.com/opopoposiop/MMDayo_AL)対応の発光強度モーフを操作できます。

## ファイル

- `archive/MobFesPenlight.pmx`
  - PMX 2.0形式のモデル本体
  - ペンライト形状2種類、合計4000本
  - 独立した発光材質4系統
  - 4系統別の色・発光強度モーフ
  - 「全ての親」「センター」ボーンによるモデル全体の移動
  - テンポ、振幅、個体差、配置範囲のモーフ
- `archive/MobFesPenlight.fxdayo`
  - 4000本をランダム配置するMikuMikuDayo用デフォーマ
  - 個体ごとに位相、速さ、振幅、向き、Y方向の上下動を変え、個体差を伴う揺れを作る
- `archive/MobFesPenlight_2.pmx`
  - 4000本、4色、全モーフを維持したGPU負荷軽減版モデル
- `archive/MobFesPenlight_2.fxdayo`
  - 1本分の動作計算を26頂点で共有するGPU負荷軽減版デフォーマ
  - 回転三角関数の共有、不要なジャンプ・停止中周期計算の省略に対応
- `MobFesPenlight_3.pmx`
  - 4000本、4色、全56モーフを維持し、形状を板ポリゴンへ置き換えたビルボード軽量版モデル
- `MobFesPenlight_3.fxdayo`
  - 1本あたり8頂点で動作計算を共有し、グリップ面と発光面をカメラ方向へ向ける軽量版デフォーマ
- `generate_mob_fes_penlight.mjs`
  - 通常版、GPU負荷軽減版、ビルボード軽量版のPMXを再生成するソース
- `validate_mob_fes_penlight.mjs`
  - 3バージョンのPMX、fxdayo、MMDayo_AL互換条件を検査するソース

## 基本的な使い方

1. `MobFesPenlight_3.pmx` と `MobFesPenlight_3.fxdayo` を同じフォルダに置きます。
2. MikuMikuDayoで `MobFesPenlight_3.pmx` を読み込みます。
3. 同名の `.fxdayo` が適用されていることを確認します。
4. モデルのモーフを調整します。

`.fxdayo` が無効な場合、4000本は原点付近で重なって見えます。これは故障ではなく、配置処理をGPU側へ任せる構造によるものです。

立体形状の通常版やGPU負荷軽減版を使用する場合は、`archive/MobFesPenlight.pmx` と `archive/MobFesPenlight.fxdayo`、または `archive/MobFesPenlight_2.pmx` と `archive/MobFesPenlight_2.fxdayo` を使用してください。PMXとfxdayoは必ず同じ番号の組み合わせにしてください。

複数バージョンを同時に読み込むと、その数だけ4000本が追加描画されます。比較時以外は通常版、`_2`、`_3` のいずれか1つだけを使用します。

## 対応環境・前提

- MikuMikuDayoでPMXとfxdayoを読み込める環境が必要です。
- 発光を使用する場合は、別途[MMDayo_AL](https://github.com/opopoposiop/MMDayo_AL)の対応ファイルを用意してください。
- `MMDayo_AL`の配布物は本リポジトリに同梱していません。利用条件は各配布元に従ってください。
- GPU負荷と見た目は、MikuMikuDayoのバージョン、レンダラー、GPU、解像度、他のモデルやエフェクトによって変わります。
- `_3`は遠景向けです。近距離や真上・真横に近い視点では、板ポリゴンのため平面的に見えます。

## GPU負荷軽減版

`MobFesPenlight_2` はペンライト数、形状、配置、4色、発光、ボーン、56モーフを通常版と同じ状態に保ち、fxdayoの重複演算を削減したバージョンです。

| 処理 | 通常版 | GPU負荷軽減版 |
|---|---:|---:|
| 1本あたりの個体動作計算 | 26回 | 1回 |
| 1グループのGPUスレッド数 | 実装既定値 | 26（1本分） |
| 回転用三角関数 | 頂点・要素ごと | 1本につきX・Y・Z各1回 |
| `Yゆらぎ=0`時のジャンプ計算 | 実行 | 省略 |
| `ゆらぎ停止=1`時の周期計算 | 実行 | 省略 |

26頂点は引き続きGPU上で並列処理し、乱数、位相、ジャンプ、回転値だけを同じペンライト内で共有します。このため、代表スレッド以外を待機させて26頂点を直列処理する方式ではありません。

個体動作の一部の計算回数を理論上26分の1に削減します。ただし、104,000頂点のボーン変換、144,000三角形の描画、MMDayo_AL、使用レンダラー、出力解像度の負荷は残るため、アプリ全体のGPU使用率を示すものではありません。

## ビルボード軽量版

`MobFesPenlight_3` は4000本、4色、配置、発光、ボーン、56モーフを維持しながら、立体形状をカメラ向きの板ポリゴンへ置き換えたバージョンです。1本をグリップ面4頂点と発光面4頂点で構成し、fxdayoが揺れの方向を保ったまま正面をカメラへ向けます。

| 項目 | 通常版・`_2` | `_3` | 削減率 |
|---|---:|---:|---:|
| 1本あたり頂点数 | 26 | 8 | 約69.2% |
| 総頂点数 | 104,000 | 32,000 | 約69.2% |
| 三角形数 | 144,000 | 16,000 | 約88.9% |

描画面数に加え、MikuMikuDayo側で更新される変形頂点や描画形状を減らすことで、`_2` の演算共有だけでは残っていたGPU負荷の軽減を狙います。実際の軽減量は、レンダラー、MMDayo_AL、画面解像度、ほかのモデルやポストエフェクトによって変わります。

板ポリゴンのため、近距離や真上・真横に近い視点では厚みがなく平面的に見えます。遠景・広角の観客席向けです。また「全ての親」「センター」でモデル全体を大きく回転した場合は、板面の向きがカメラに完全一致しないことがあります。形状の立体感が必要なカットでは `_2` を使用してください。

## モデル全体を移動する

| ボーン | 役割 |
|---|---|
| `全ての親` | モデル全体を移動・回転します。センターの位置もまとめて動かしたい場合に使用します。 |
| `センター` | ペンライト4000本を移動・回転します。全ての親を基準位置として残したい場合に使用します。 |

ボーン操作画面の `Root` 枠から `全ての親`、`センター` 枠から `センター` を選択できます。両ボーンの移動は、fxdayoによる会場配置と揺れにも親子変換として加算されます。

## MMDayo_ALを使う

1. MMDayo_ALから `PPAL_2.pmx` と `PPAL_2.fxdayo` を用意し、同じフォルダに置きます。
2. MikuMikuDayoでペンライトモデルに加えて `PPAL_2.pmx` を読み込みます。
3. `PPAL_2.pmx` のモーフで画面全体の発光、ぼかし、光芒を調整します。
4. ペンライトモデル側の `色1_AL強度`～`色4_AL強度` で、各色群の発光を個別調整します。

`PPAL_2.pmx` のコントローラーモーフは次の9個です。

| モーフ | 役割・値の目安 |
|---|---|
| `off` | エフェクトの消灯。`0`で全開、`1`で消灯 |
| `発光強度` | Si方式の発光強度。`0`で標準（×1）、`-1`で消灯、`+1`で×2 |
| `ぼかし幅低減` | ぼかし幅の低減。`0`で最大、`1`で最小 |
| `光芒数` | 光芒の方向数。`0`～`9`、`0`では光芒なし |
| `元画面輝度` | 合成前の元画面の輝度。`0`で変化なし、`-100`で完全な黒、`+100`で×2 |
| `AL-Z発光強度` | AL-Z方式の発光強度。`-100`～`500` |
| `光芒角度` | 光芒全体の回転角度。度単位 |
| `光芒長さ` | 光芒の長さ。`-100`で長さ0、`0`で標準、`+100`で×2 |
| `点滅周期` | 発光全体の点滅周期。正値は滑らかな波、負値は矩形波、`0`は停止 |

発光強度には `発光強度` と `AL-Z発光強度` の両方が掛かります。`点滅周期`が正の場合は発光倍率が約`0.2`～`1.0`の範囲で滑らかに変化し、負の場合は点灯と消灯を交互に切り替えます。計算上の全体倍率は次のとおりです。

```text
発光倍率 = max(0, 1 + 発光強度) × max(0, (100 + AL-Z発光強度) / 100) × saturate(1 - off) × 点滅倍率
```

本モデルはMMDayo_ALの「方式A：材質指定」に準拠しています。

- スペキュラ色：黒 `(0, 0, 0)`
- 初期Shininess：`110`
- MMDayo_AL内部の初期発光倍率：`(110−100)/10 = 1倍`
- 各 `AL強度` モーフを1にした場合：Shininess `180`、発光倍率 `8倍`

ペンライト側の材質倍率へ、PPAL側の `発光強度`、`AL-Z発光強度`、`off` による全体倍率がさらに掛かります。過度に白飛びする場合は、まずペンライト側の `AL強度` を下げてください。

## 4色の独立モーフ

`色1`～`色4` は、それぞれ別の1000本と別の発光材質を操作します。

| 系統 | 初期色 | 対象 |
|---|---|---:|
| `色1` | 緑 | 1000本 |
| `色2` | 桃 | 1000本 |
| `色3` | 青 | 1000本 |
| `色4` | 橙 | 1000本 |

各系統には次の11モーフがあります。例として色1を記載します。

| モーフ | 役割 |
|---|---|
| `色1_H赤`～`色1_H桃` | 色相プリセット8色 |
| `色1_S0` | 彩度を下げて白へ近づける |
| `色1_V50` | 明度を約50%へ下げる |
| `色1_AL強度` | MMDayo_AL発光を1倍から8倍へ上げる |

色2～色4も同じ構成です。たとえば `色1_H赤`、`色2_H青`、`色3_H黄`、`色4_H桃` を同時に使用できます。

同じ系統内では、色相Hモーフを基本的に1種類だけ使用してください。複数の色相を同時に上げると、PMXの加算モーフ仕様により色が混ざります。別系統どうしの色相モーフは同時に使用できます。

色相H、彩度S、明度Vの全40モーフは、PMXのモーフ分類「目」に配置しています。`AL強度` と `AL消灯_全体` は、PMXのモーフ分類「リップ」に配置しています。

`AL消灯_全体` を1にすると、4系統すべてのShininessを100未満へ下げ、MMDayo_ALの発光判定から外します。

## 動きと配置のモーフ

| モーフ | 役割 |
|---|---|
| `テンポ` | 0で60 BPM、1で240 BPM |
| `振幅` | 全軸の振りをまとめて増幅する |
| `X振幅` | X軸だけを独立して調整する |
| `Y振幅` | Y軸だけを独立して調整する |
| `Z振幅` | Z軸だけを独立して調整する |
| `Yゆらぎ` | 0で上下動なし、1でジャンプ型の上下動 |
| `ゆらぎ停止` | 0で通常動作、1で三軸の振りとY上下動を停止 |
| `同調` | 0で個別動作、1で集団同期 |
| `ばらつき` | 個体ごとの動きの差を増やす |
| `配置幅` | X方向の会場幅を最大3倍へ広げる |
| `配置奥行` | Z方向の会場奥行を最大3倍へ広げる |

テンポは `60＋180×モーフ値` で計算され、三軸の振りとジャンプ型上下動の両方へ同じBPMが適用されます。

初期配置は幅約113.137、奥行約79.196です。従来の80×56から縦横比を保って各軸を√2倍し、初期配置面積を正確に2倍にしています。

`Yゆらぎ` はジャンプを模した5段階の動作です。

1. 踏み切り前の沈み込み
2. 身体を伸ばす踏み切り
3. 標準重力加速度 `9.80665` による放物運動
4. 着地衝撃を吸収する沈み込み
5. 通常の手元高への復帰

各ペンライトは個別の周期、位相、沈み込み量を持つため、全員が同時に同じ高さで跳ねません。

時間変化する回転振幅は、X軸とZ軸が従来値の3倍、Y軸が従来値の5倍です。`X振幅`・`Y振幅`・`Z振幅` は、0で各軸の基準倍率、1でさらに2倍です。数値入力で-1にすると、その軸の振りだけを停止できます。

`ゆらぎ停止` を1にすると三軸回転と重力式Y上下動の時間変化をまとめて止めます。会場内の配置と、個体ごとの静的な向き・傾きは維持されます。

`同調` は、ランダムな速度・位相・振幅・ジャンプ周期を共通テンポへ漸次近づけます。

| 値 | 状態 |
|---:|---|
| `0` | 完全に個別のランダム動作 |
| `0.25` | 実同調率約43.8%。早い段階でまとまりが見える |
| `0.5` | 実同調率75%。強い一体感 |
| `0.75` | 実同調率約93.8%。最大状態に近い |
| `1` | 従来どおりの最大同調状態 |

0～1の途中値には `1−(1−値)²` の減速カーブを使用し、低いモーフ値から同調効果が分かるようにしています。回転角度とジャンプ周期は最短の位相方向で補間するため、スライダー操作中に急な逆回転やジャンプ時刻の飛びが起きにくい構造です。

値1でも全4000本を完全な同位相にはせず、64本単位の小グループごとにわずかな遅れを残します。集団としての一体感を保ちながら、機械的なコピー動作になるのを防ぎます。

## ユーザーが変更してよい箇所

`archive/MobFesPenlight.fxdayo` の「ユーザーが変更してよい箇所」にある次の値は、数字だけ変更できます。

- 基準テンポ
- 配置の幅と奥行
- 手元の高さ
- 基準振幅と傾き
- X・Y・Z軸の基準振幅倍率
- 重力加速度とYゆらぎの倍率
- 配置モーフの最大倍率

本数を変更する場合は、`generate_mob_fes_penlight.mjs` の `INSTANCE_COUNT` に加え、`.fxdayo` の次の3項目も合わせる必要があります。

- `MOB_INSTANCE_COUNT`
- `MOB_TOTAL_VERTEX_COUNT`
- `MOB_VERTICES_PER_INSTANCE`（形状を変えない限り26のまま）

## ユーザー変更不可の箇所

PMX生成処理のバイナリ書き込み部と、fxdayoの「ユーザー変更不可の箇所」はPMXの頂点順に直結しています。部分的に変更すると、形状崩れ、表示欠け、GPU書き込み範囲の不一致が起きます。

発光材質のスペキュラ色とShininessはMMDayo_ALの判定値です。用途が分からない場合は直接変更せず、`色1_AL強度`～`色4_AL強度` を使用してください。

## 再生成と検証

Node.jsが利用できる環境で、このフォルダをカレントディレクトリにして実行します。

```sh
node generate_mob_fes_penlight.mjs
node generate_mob_fes_penlight.mjs --optimized
node generate_mob_fes_penlight.mjs --billboard
node validate_mob_fes_penlight.mjs
```

1行目は `archive/MobFesPenlight.pmx`、2行目は `archive/MobFesPenlight_2.pmx`、3行目は `MobFesPenlight_3.pmx` を生成します。

検証成功時は先頭に `VALID` と表示されます。これはPMX・fxdayo・ソース上の構造検証であり、すべての環境での表示品質や性能を保証するものではありません。検証内容は次の通りです。

- PMX署名、バージョン、全セクションの読み取り
- 頂点・面索引・材質・ボーン・モーフの整合性
- 「全ての親」「センター」が移動可能で、全頂点へ親子変換が伝わること
- fxdayoの会場配置後にボーンスキニングを行い、配置全体を移動・回転できること
- PMX末尾まで余剰や欠損なく読めること
- 4つの発光材質が別色で、それぞれ面を持つこと
- 4材質すべてがMMDayo_ALのスペキュラ色・Shininess条件を満たすこと
- 4系統すべてに独立したHSV系モーフとAL強度モーフがあること
- 全色関係モーフがPMXの「目」分類に設定されていること
- 全発光関係モーフがPMXの「リップ」分類に設定されていること
- `Yゆらぎ` が沈み込み・踏み切り・重力滞空・着地・復帰を持つこと
- X・Y・Z軸の基準振幅倍率が3倍・5倍・3倍であること
- X・Y・Z軸それぞれに独立した振幅モーフがあること
- `ゆらぎ停止` が三軸回転とY上下動の両方へ適用されること
- `テンポ` が0で60 BPM、1で240 BPMになり、全動作で共通使用されること
- `同調` が三軸回転とジャンプの速度・位相・振幅へ適用されること
- 同調0～1が低い値から効果の出る減速カーブで補間されること
- 回転角度とジャンプ周期が最短の位相方向で補間されること
- 同調後も64本単位の小グループ差が残ること
- 初期配置面積が従来値の2倍であること
- 配置幅・配置奥行のモーフ最大値が3倍であること
- YRZFX JSONと制御モーフ名の一致
- PMX頂点数とfxdayo側定数の一致
- GPU負荷軽減版のスレッドグループ幅が1本分の26頂点と一致すること
- 個体位置・回転値をgroupsharedで共有し、同期後に全頂点へ適用すること
- 回転用三角関数がX・Y・Zの3回へ集約されていること
- `Yゆらぎ=0`と`ゆらぎ停止=1`で不要な計算を省略すること
- ビルボード軽量版が1本8頂点、合計32,000頂点、16,000三角形であること
- ビルボード軽量版がカメラ方向から板面の右・上・法線を組み立てること
- ビルボード軽量版でも個体の揺れ、配置、ボーン変換、4色、56モーフを維持すること

通常版と `_2` のモデル形状・仕様は同じです。`_3` は動作・操作仕様を保ち、形状だけをビルボード用に軽量化しています。

配置は実行のたびに変わる乱数ではなく、ペンライト番号から計算する再現可能な疑似乱数です。同じ設定なら毎回同じ会場配置になり、アニメーション編集時に位置が飛びません。
